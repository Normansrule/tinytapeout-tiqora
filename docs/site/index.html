Hardware timing for Tiny Tapeout, no processor

Tiqora-Serial

Exact time, from your computer.

The timing unit of the Tiqora microcontroller, byte for byte, with no processor: a host sends six-byte commands over the demo board's USB serial port to arm triggers that fire on an exact clock tick and to read back timestamped pin edges. It is built for SkyWater sky130 through Tiny Tapeout, at 1x2 tiles.

Fire a deadline

The host writes a tick number into a deadline register and goes back to whatever it was doing. When the timebase reaches that tick, the pin rises on exactly that clock, with no help from the host. Pick how far ahead to arm it.

What goes in and what comes out

Seven questions

What is Tiqora-Serial?

A Tiny Tapeout design of 1 × 2 tiles that timestamps edges on eight inputs and drives three trigger outputs on exact clock ticks, all controlled by a host computer over a serial port. The timing RTL in src/sync/ is the same file, byte for byte, as in the Tiqora microcontroller, which make -C test shared checks. Use it when the thinking happens on a PC or a Raspberry Pi and only the timing has to be exact.

What enters?

Commands on ui_in[3], at 115,200 baud from the demo board's RP2040 USB bridge: write 01 addr d0 d1 d2 d3, read 02 addr, ping 03, least significant byte first. Edges on CAP0 to CAP7 (ui_in[0:2], ui_in[4:7], uio[0]). One 50 MHz clock and an active-low reset.

What happens inside?

The receiver turns serial bits into bytes; the host port collects a command, touches one register of the timing unit for exactly one clock, and replies. Meanwhile the timing unit counts ticks, stamps edges into a two-deep queue and compares the time against armed deadlines on every clock. A ping and a write · a deadline · an edge, queued and read.

What comes out?

Replies on uo_out[4]. TRIG0 to TRIG2 on uo_out[2:0], rising on the programmed tick. EVT, EVTP and OVF on uo_out, and the queue's count, channel and edge on uio, so a board can react to an event without asking. The pinout.

What exists today?

SystemVerilog RTL, a Python host library and command line, testbenches, a Basys 3 FPGA build and Tiny Tapeout packaging. No chip and no board run. At the 1x2 size info.yaml submits, the layout is clean: the Tiny Tapeout gds, pre-flight and gate-level workflows pass (GitHub run 40161260168). Physical design.

What is proven or measured?

measured 48 RTL checks, 5 cocotb tests, 13 tour checks, synthesized cell area. measured at 1x2: DRC, LVS and antenna clean, pre-flight and gate-level tests pass, setup met at the typical corner. failed setup at the slow corner (ss_100C_1v60) by 1.30 ns at 50 MHz. not yet formal proofs, a shuttle, silicon. The evidence ladder.

What can I try?

# Icarus Verilog 12 and Python 3
git clone https://github.com/Normansrule/tinytapeout-tiqora
cd tinytapeout-tiqora
make -C test tour                # the recorded session: 13 checks
python3 docs/tools/traces.py     # decode it and check every reply against the protocol model
make -C test sim                 # every suite

Or build any command in the protocol lab, including wrong ones, and see what the chip answers.
