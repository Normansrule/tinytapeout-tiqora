Tours of a serial session

One simulation of the submitted top module, tt_um_normansrule_tiqora_serial, driven only through its pins at 115,200 baud, the way the demo board's USB bridge drives it. Every byte below was decoded from the pin trace, and every reply was checked against an independent model of the protocol before this page was built.

How to read it. A serial byte takes 4,340 clocks, so the trace keeps only the clocks where something changed; the cursor moves from change to change. The byte rows show each byte on the wire, host to chip and chip to host. The table beside the waveform gives every value at the cursor. The recorded label stays on every sequence; the protocol lab further down is computed in your browser.

Protocol lab: send your own bytes

Type bytes in hex, or add commands with the buttons, and see how the host port reads them: what each command does and what it answers. Try an unknown command, or a write that stops half way. The model is hostPort in docs/site/lib/model.js.
